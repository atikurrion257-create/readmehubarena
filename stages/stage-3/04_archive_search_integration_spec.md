# Stage 3 — Missing archive/search integration: build contract

The following is a precise implementation target, not working PHP. Stage 1's delivered plugin does **not** implement these components. Keep the corresponding pages blocked until implemented and tested in an approved staging environment; do not paste a shortcode name that has not been registered. The host child theme or a small extension of the Stage 1 plugin may supply server-rendered components, rendered as Elementor Shortcode widgets after registration, always with Element Caching = Inactive. No Elementor Pro, native PHP in a page, external search service, or fabricated content.

## Shared result contract

- Query only published, publicly viewable editorial `page`/`post` records; never return draft, private, password-protected, unindexed internal `rmh_tool` records or the archive itself. Escape text, URLs and attributes using the appropriate WordPress APIs; validate filters against the locked silo map. Use accessible labels, GET forms, semantic `article`, an H3 link, a text excerpt, and a `nav` for pagination. Never print an affiliate URL in a card.
- Capture current page with a distinct namespaced, bounded positive integer. Carry approved filters and search terms into Previous/Next URLs; omit empty parameters. Query `posts_per_page=12`, use stable `date DESC, ID DESC`, and reset post data. Return no duplicate results between pages. Cards link to the actual public permalink, not a draft. Use properly sized lazy images if present, empty alt for decorative thumbnails, otherwise omit image. Omit unavailable author/date data; never invent it. Render the exact empty state from the respective Page File when there are no results. Escape user input, avoid database interpolation, and test malformed filters and large page numbers.
- Stage 1 uses page meta `rmh_page_template_type`, `rmh_silo_slug`, and `rmh_cluster_slug`. Archive inclusion must use explicitly verified template assignments rather than broad query assumptions; verify the stored values against actual WordPress/ACF and include the silo URL pages in editorial results as appropriate. Pagination/filter URLs should canonicalize to the archive base under the site SEO policy; confirm with Rank Math and exclude filter pages from indexing when required.

## Blog T4

Query published informational articles marked T5. Featured card: the most recent eligible article under the stable ordering, visible only if one exists. Latest cards use the same query and exclude the featured ID so the card is not repeated; paginate the remaining query. If no featured article, show the stated empty message once and suppress an empty second list. Cards display linked title, excerpt, actual author/date, and optional image. Category links go only to published hubs. Do not classify commercial T3/T8/T9/T10 as informational blog articles without an owner-approved content model change.

## Comparisons T7

Query published editorial pages marked T8. Include native GET selectors for silo and category derived from the locked taxonomy map; validate the category belongs to its silo. Filter query by corresponding page meta `rmh_silo_slug` and `rmh_cluster_slug`. Provide labels “Silo”, “Category”, “Filter”, “Reset filters”, with All options; retain values through pagination. Cards use the published comparison title and excerpt. When no result matches, use the comparison Page File's empty message, adjusting only its first sentence to “No comparisons match these filters.” if the overall archive is not empty.

## Search T13 and 404

Use WordPress's native search infrastructure and escaped search terms. Register an explicit `/search/` route and GET query handling, or document an equivalent rewrite so the field submits there and a refresh retains `s`. Render only published public page/post results; filter types Tools (published reviews T3 only, never registry records), Articles (T5), Comparisons (T8), Deals (T12, applying the same actual verification/status safeguards as deals list), and All. Match type using the stored page-template field, not the URL alone. Validate the type against this allowlist, use GET, preserve query and type for pagination, and enforce the noindex/sitemap rule on all variants. A native synchronous request has no loading skeleton; if an optional async enhancement is later supplied, its accessible status text is “Searching…” and it must fall back to the synchronous form. No fabricated loading results. On a genuine 404, the child-theme `404.php` calls `status_header(404)`, `nocache_headers()` as appropriate, emits `X-Robots-Tag: noindex` or a noindex robots tag, includes normal `wp_head`/`wp_footer` hooks, and presents the T20 copy and native search form. Test that unknown URLs return HTTP 404, not a 200 page.

## Release tests

Use fixtures of published, draft, private, password-protected and internal records; test filters, absent metadata, zero/one/multiple results, pagination boundaries and repeated/hostile input. Confirm search and 404 routing, noindex and response status over HTTP. Check keyboard/assistive technology, 200% zoom and the five viewport widths. Verify no duplicate query/cache results or schema, no unpublished links, and no new third-party tracking. These tests are not run by the static Page File validator.
