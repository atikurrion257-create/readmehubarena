# Six synced-template skeletons — draft Gutenberg markup

The six HTML files are Gutenberg block-comment markup. Copies in the plugin `patterns/` folder are provisioned only when an operator explicitly runs `wp rmh provision-synced-patterns` on a staging site. This creates six published `wp_block` posts, WordPress's synced-pattern representation. It does not run on activation and does not publish pages. Published reusable blocks are nevertheless a persistent write: do not run on production without explicit approval. The command finds previously provisioned blocks by a private meta marker and never overwrites editor changes, including when a block is trashed. Review any incomplete command result before retrying.

These are structural scaffolds, not publication-ready articles: add verified prose, real titles, sources, qualifying rationale and 5–8 visible buyer FAQs as required. Add CTAs solely through `rmh_affiliate_cta` after disclosure and proof, with a verified tool slug. Empty-attribute shortcodes remain inert until configured. T5 has no sales banners. T12 requires manually verified, current offer status and terms.

**Shared-edit warning:** an edit to a synced pattern changes all its instances. Full articles contain unique content; detach a template pattern before adding page-specific headings, evidence or copy, or sync only genuinely shared components. The ordinary five registered component patterns use `register_block_pattern()` and are not synced. Test provisioning, insertion, shared updating, unsyncing and deletion/re-run in the actual staging editor before deployment; no production blocks have been created.
